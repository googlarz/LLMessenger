# Production Performance Baseline - 2026-07-13

This baseline is enforced by `ProductionReadinessPerformanceTests` on every full test run.

## Corpus

- 100,000 messages
- 1,000 conversations
- 4 services
- 2,000 unattached messages eligible for the next automatic brief
- FTS5 indexes and triggers enabled
- On-disk SQLite database using the production migration chain

## Measured Result

Measured on an Apple Silicon development machine with a Debug test build:

| Operation | Result | Gate |
| --- | ---: | ---: |
| Fetch 2,000 pending messages | 0.008 s | < 2.0 s |
| Fetch 500 service-scoped pending messages | 0.002 s | < 2.0 s |
| Ranked FTS search, 50 results | 0.001 s | < 2.0 s |
| SQLite storage for 100,000 messages | 53.9 MiB | < 256 MiB |

The latency gates are intentionally much wider than the local result so slower CI hardware can enforce regressions without becoming flaky.

## Structural Gates

- General pending-message reads must use `messages_on_briefId_isSent_timestamp`.
- Service-scoped pending-message reads must use `messages_on_briefId_isSent_service_timestamp`.
- Neither query may degrade to `SCAN messages`.
- Brief prompt assembly remains bounded to four SELECT statements regardless of conversation count.
- Automatic generation remains bounded by message, conversation, prompt-token, and per-run job limits.

## UI Work Removed From Main Actor

- Archive message and brief FTS searches execute in a detached task after a 200 ms cancellable debounce.
- Contact profile and recent-card reads execute in a detached task.
- Brief cards use their batch-loaded conversation context for edits and undo state instead of synchronously reading SQLite during interaction.
